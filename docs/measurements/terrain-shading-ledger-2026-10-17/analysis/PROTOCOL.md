# Shading ledger analysis protocol — frozen before GPU data

This analysis reads saved JSON only. It does not build a model, cast rays, use the browser, sample a texture, or submit GPU work. Input files are `../browser/shading-ledger.json` and `../face-witness-reuse/faces12.json`; output is a separate JSON/Markdown analysis with input SHA-256 identities. The twelve historical IDs, order and native 2474×1844 pixel coordinates remain fixed. Historical `artifact`/`control` labels are not current image classifications.

Required current input schema is the Engine report: `cached`, `fresh` and `restored` whole-target records, each with `sha256`, dimensions and `witness`; `shadingLedger.rows` with `id,x,y,records[macro-normal|final-normal|factors]`, each `rgba` and raw uint32 `bits`; `snapshot.lighting.sunDirection`; and `installedGeometry[position|normal|terrainSurface|index]`. Root flags `ledgerDistanceQualified`, `ledgerValuesQualified`, `shadingQualified`, `stable` and `cacheStateQualified` must all be true. The probe must report complete/restored/stable and a fulfilled, settled owner drain. These flags are cross-checked against the saved values, not accepted as substitutes for them.

The installed CPU-side browser attribute views must match all four pinned canonical SHA-256 values and byte counts: position `4c7e3f0b92c294850dad4014d3c260e0cb922ba5ade13a952722240a2e5ecc64` / 7,101,456 B; normal `3cb820d4d203c89f61e8e26809ddbdcd2f8ce2645dce0842b758a1b0ea6dcbfd` / 7,101,456 B; terrainSurface `7595b45c14d4d249df98d99145fcaa485b21d62e419764b99ce4fedc780c76f2` / 4,734,304 B; index `87e1b8d5b569577c291efefb1698ca66b657ecb3f9c73dcf6ddc73316a1030ae` / 14,190,600 B. This is a CPU view identity gate, not a GPU buffer readback or winner-face certificate.

Require all three current whole-target hashes equal and native dimensions unchanged. Join all three ordinary witness arrays and the ledger by exact IDs/coordinates; require ordinary RGBA bits identical in cached/fresh/restored. Decode record floats directly from their saved little-endian uint32 words and cross-check the JSON numbers. Require finite values and positive distance. All **36** diagnostic distance words must equal the corresponding fresh ordinary distance word exactly. RGB clear sentinel `[-8192,-8192,-8192]` is invalid; its clear alpha is 1.

For each point compute macro/final normal lengths and signed dot products with the recorded Sun, angle between their normalized directions, and their signed dot difference. Unit-length error is `abs(length−1)`; a fixed `1e−5` threshold is a numerical consistency flag, not a physical accuracy tolerance. Report both strict sign crossing (`macroDot*finalDot < 0`) and crossing outside a fixed `1e−6` near-zero band. Compare saved D with `max(0, dot(finalNormal, recordedSun))`, retaining signed/absolute residual; `1e−5` is the fixed arithmetic-consistency threshold. D, S and V ranges are checked with that same tolerance against `[0,1]`, `[0.45,1]`, `[0,1]`. Recorded Sun unit-length error must also be at most `1e−5`; no silent normalization is used for dot products.

Compute ordinary linear luminance with `(0.2126,0.7152,0.0722)`. For L1/L2/L3 historical artifact/control pairs, retain RGB and luminance deltas, artifact/control ratios, relative luminance delta and signed Michelson contrast, plus macro/final dot and D/S/V deltas and ratios. Every zero denominator produces null with no invented replacement. A ground-branch light multiplier may be reported from the saved solar/ambient RGB, `.90*solar*D*V + 1.12*ambient*S`; it is not an inversion of the ordinary image, which also has water/sea terms.

Join historical face normals only after current identity/distance gates and the saved face provenance permit it. Retain their original faceIndex/corners/normal/dot, compute saved-arithmetic face dot and face-to-macro/final angles, and mark them explicitly **historical CPU raycaster face reference**. Even canonical CPU views plus source/camera continuity and matching receiver distances do not certify the current GPU raster winner, fragment derivatives or GPU face identity. No new face lookup or resampling is allowed.

Historical reference pin, frozen before the GPU ledger: faces12 SHA-256 `d8420acc356e1026cc1ae5278c43ec631568030cf8c19fd96d92e06cf10b708a`, schema `cloudia-historical-cpu-face-reuse-v1`, source report SHA-256 `ec3187ebc895e0aed4e3bd723d995e0196aa2825fa3167ea4e03c78898348d43`. Its camera components/projection inputs were explicitly fround in the archived helper: compare those with float32-rounded current snapshot values exactly. Compare the historical light Sun with current recorded Sun within fixed `1e−12` absolute error, recording the error. These are continuity gates for a CPU reference, not a relaxation of the 36 exact current GPU distance-bit comparisons. Historical CPU distance minus current GPU distance is reported arithmetically, without an invented CPU/GPU identity tolerance.

All gates and arithmetic consistency results are reported separately. Failed gates produce an unqualified result and no causal attribution. The script never picks another pixel, tunes a parameter, discards a difficult pair, or asserts artwork, global ribbon shape, physical sunlight, terrain truth or FPS. Script/schema work may use structural keys; no GPU ledger outcome is assumed before the actual saved input exists.
