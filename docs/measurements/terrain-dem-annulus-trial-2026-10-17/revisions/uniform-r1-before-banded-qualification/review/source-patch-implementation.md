# Source DEM patch — implementation ready for static review

API: `TerrainMeshOptions.sourcePatch?: {coreHalfExtentKm:number; outerCutKm:number}`. Root supplies `48` and the actual Float32 ring boundary `Math.fround(94*.512)`. The source-node spacing, origin, dimensions and limits come from the already validated refinement metadata. The helper imports only types from terrainMesh and receives the canonical sphere function as a callback.

OFF follows the existing builder/refinement and final normal accumulation. The original outer lookup loop and arithmetic remain in place; patch candidate enumeration runs only when the optional lookup exists. Exact OFF buffers/statistics and the historical stream still require root's planned verification.

B retains old outer faces in original cell order, remaps vertices through an Int32 table, and copies their Float32 position/surface values. A cut crossing any old face throws. All four cut chains must have complete consecutive edges and shared corner IDs, including existing refinement midpoints. The replacement uses source nodes with two SW→NE faces per cell. Four monotone zipper strips reuse both boundary chains without new seam vertices. Winding/count/budget failures throw; no truncation occurs. Shared geometric normals are accumulated once over the assembled mesh, so normals incident to the seam can change.

Lookup uses arithmetic core cells, per-side CSR seam bins and the retained outer cell table. The same barycentric arithmetic and maximum-height boundary rule evaluate every candidate. A small routing margin derives from the actual projected seam face span and the existing −1e−7 barycentric tolerance. The outer cell table covers only the outer prefix; it deliberately does not claim to cover the appended core and seam faces.

`stats.sourcePatch` names core/outer/seam counts, source spacing, new sample calls and total lookup bytes. The old one-pass refinement metadata is qualified as `sourcePatch.prePatchRefinement`, not presented as the combined mesh's refinement result. Total sampleCalls include the discarded interior preparation work. Current `stitchedCells` counts retained ordinary ring stitch cells through the parent's existing stitchEdge function; `prePatchStitchedCells` preserves the old counter separately. Zipper triangles have their own seam count. CPU lookup bytes include CSR storage; geometryBytes retains the existing attribute/index payload convention.

Pre-run theoretical bound for this actual configuration remains ≤822,873 vertices, ≤1,644,720 triangles, ≤46,068,576 attribute/index bytes. New source calls: 591,361. Construction also retains ordinary/refined temporaries until collection and performs one final incident-normal accumulation (≤19,748,952 bytes for that accumulator). These are payload/work bounds, not measured RSS, runtime, GPU or FPS results. The original 1M/2M/64MiB geometry limits remain enforced; root will measure actual costs.

Six small fixture tests are prepared: OFF exact, source-node values and sampling counters, welded edge incidence/corners/Euler/winding/unit normals, actual-triangle brute-force lookup comparison, malformed configuration rejection and all three output budget overflows. No test, compilation, mesh/model, scalar or GPU execution was performed by the implementation agents. Root's source freeze/review precedes any execution; scalar PASS alone does not qualify the seam, whole geometry, near view or visual result.
