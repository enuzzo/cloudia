# Close approach — bounded CPU boundary probe

14 October 2026. First concrete follow-up to the cloud renderer research: improve camera placement before changing near-cloud material or light. Shader appearance and quality budgets are unchanged.

## Defect and change

The old search took 192 samples from the panorama position toward the cloud center. Portrait framing moves that starting point farther away, so sampling became coarser. A 40-metre foreground layer at z=3.021…3.061 km is missed entirely by the old 16 km /192 search; the regression test now finds it and adds the existing 3 m margin.

The new search clips to the cloud's conservative world bounds (including drift), then samples with a target spacing of 12.5 m. A 2048-interval cap bounds CPU work; the actual spacing and whether a boundary was found are recorded. Ten bisection steps refine the first detected threshold crossing. Parallel rays, missed bounds, empty volumes and malformed coordinates are handled. Rotation invalidates the previous estimate immediately rather than retaining the old ray's boundary for up to150 ms. The CPU ice blend now uses the same smoothstep as the shader.

This is still an approximate boundary at density>0.025. Features thinner than the actual spacing, weaker vapor, GPU interpolation, evolving flow and extra near micro-erosion can disagree. The 3 m value is an added camera margin, not a certified distance from every visible wisp. The UI therefore says “Avvicinamento massimo · distanza stimata” rather than asserting it has reached a measured surface.

## Repeatable audit

Run `bun scripts/qa-approach.ts /private/tmp/cloudia-approach-audit.json` after checking the node_modules Dropbox exclusion. This generates the actual full256³ density/light volume and128³ detail for seed1571198069, fixes the cloud time at60s, and compares18 yaw/pitch/aspect combinations against a dense2.5m CPU search. It uses fixed wind/drift listed in the JSON, independent of browser/GPU state.

The ordinary cloud cases were already close to the dense reference; the thin-layer regression is the clear correctness gain. Do not present these numbers as a visible photorealism improvement, GPU benchmark or proof of performance on other devices.

## Integration and remaining checks

- Fixed-reference controls now reset displayed wind/dispersion/rain values as well as their percentages; tab-only controls still send no renderer actions.
- Tests cover the thin layer, portrait invariance, translated/parallel rays, empty/bounded work and diagnostic UI reset.
- Rendered UI/near-camera/rotation checks are still blocked by the prior localhost browser-policy denial. No alternative browser route was used. The prior visual acceptance gates remain open.
